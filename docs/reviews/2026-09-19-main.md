## Summary
This change expertly integrates the modular two-stage OBIA detection pipeline into a unified, backward-compatible CLI command. The architecture robustly handles end-to-end execution, deliverable export, and zero-candidate edge cases without breaking the legacy U-Net and RF paths. However, there are gaps in test coverage around new error-handling branches, and a few minor silent failure modes in argument parsing and rasterization that should be tightened up before merge.

## Major
### 🟠 Missing test coverage for new error handling paths, `testing/test_detect_oil.py:118`
**Problem**: The tests cover the `ValueError` for unknown modes, but they do not cover the new exception branches introduced in this PR: `FileNotFoundError` when no default models exist during mode resolution (`detect_oil.py:1091`), `FileNotFoundError` when the selected OBIA bundle is missing (`detect_oil.py:1205`), and `RuntimeError` when `ObjectClassifier` cannot be loaded (`detect_oil.py:1209`).
**Why it matters**: The project specifies `TEST_SIGNAL=configured`, meaning new branching logic and error handling must be covered. Untested error branches risk crashing ungracefully or throwing incorrect exception types when environment configurations change.
**Suggested fix**: Add unit tests in `testing/test_detect_oil.py` (using `pytest.raises`) that mock empty directories or missing files to assert these specific exception paths are triggered correctly.

## Minor
### 🟡 Silent override of explicit user model path, `testing/detect_oil.py:1049`
**Problem**: In `resolve_pipeline_mode`, if a user explicitly sets `--mode unet` but provides a `--model` that does not end in `.pt` or contain `"unet"` (e.g., `--model weights.pth`), the script silently discards their argument and falls back to `default_unet`.
**Why it matters**: Silently ignoring user configuration is a leaky API contract. If a user tries to load valid PyTorch weights saved with a `.pth` extension, they will silently run inference on the default model instead, causing severe debugging confusion.
**Suggested fix**: If the mode is explicitly set to `unet`, trust the user and use their provided `--model` path regardless of its extension, or explicitly throw an error if the extension is strictly forbidden.

### 🟡 Silent omission in candidate mask rasterization, `testing/detect_oil.py:825`
**Problem**: In `rasterize_confirmed_slicks`, if `candidate_mask` is provided, the function loops through slicks and sets the mask pixels using `candidate_mask == lid`. However, if `lid` (from `getattr(slick, 'label_id', None)`) is `None`, that slick is silently skipped without falling back to its spatial geometry.
**Why it matters**: If a slick object is constructed or mocked without a `label_id`, it will simply vanish from the final `mask.png` output without warning.
**Suggested fix**: Inside the loop, if `lid` is `None`, fall back to rasterizing the slick's geometry or bounding box as is done in the bottom half of the function.

## Nits

- ⚪ `testing/test_detect_oil.py:308`, same unclosed file handle issue for `Image.open()`.

## Strengths
- The `rasterize_confirmed_slicks` fast path cleanly returns an empty zero-array when no slicks are present, preventing `rasterio` from throwing cryptic geometry errors.
- Excellent backward compatibility; the script thoughtfully preserves all legacy `--model` and `--no-vessel-masking` behaviors while introducing the advanced pipeline gracefully.

## Test coverage
The core happy paths, calm water zero-candidate edge cases, and overriding threshold behaviors are thoroughly covered by `test_detect_oil.py`. However, as noted in the major finding, test coverage is missing for the new error exception branches (`FileNotFoundError` and `RuntimeError`) during model loading and mode resolution.
